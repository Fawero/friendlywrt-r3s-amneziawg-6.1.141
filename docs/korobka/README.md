# Коробка — документация проекта

Дата фиксации: **8 сентября 2026 года**. Редакция требований: **1.2**.

Этот раздел сохраняет результаты обсуждения тиражируемой коробки на NanoPi R3S / R3S LTS. Он является актуальной точкой входа для продолжения проекта. Последние уточнения владельца имеют приоритет над прежними черновиками: дополнительные конфигурации загружаются в любой момент; дополнительного VPS нет; ручного ввода внешнего IP, домена и портов в мастере нет; Surfshark не является отдельной сущностью продукта.

**Статус:** требования и проект архитектуры, не готовая прошивка. В рамках этой фиксации устройство не обследовано, пакеты на нём не установлены, мастер и панель не реализованы. Существующий `amneziawg.ko` — прежний артефакт для конкретного ядра, а не подтверждённая сборка нового продукта с AWG 3.1.

## Суть продукта

Один воспроизводимый образ microSD с ПО, шаблонами и проверенным пресетом. После локальной активации каждый экземпляр получает собственные доступы и загруженные владельцем конфигурации. Рабочую персонализированную карту не используем как общий образ для других владельцев.

```text
Домашние устройства -> Podkop -> выбранный исходящий AWG -> интернет
Telegram -> MTG -> локальный SOCKS секции Podkop -> выбранный AWG -> Telegram
Телефон -> отдельный входящий WireGuard -> разрешённая домашняя сеть / интернет
Панель и LuCI -> только доверенная домашняя LAN, после авторизации
```

Исходящих профилей может быть больше трёх; три назначения не означают лимит числа файлов. Один профиль может обслуживать несколько назначений. Параметры соединения берутся из загруженного файла, подходящий клиентский пресет добавляет система.

Внешний доступ — напрямую через публичный IPv4 владельца. Условие об услуге «Белый IP» показываем явно. Отдельный VPS, ретранслятор и обязательная облачная панель исключены. Фактическую входящую доступность не приравниваем к обнаружению публичного адреса.

## Следующая точка продолжения

1. Выполнить read-only обследование **новой** коробки и разобрать вывод приватно.
2. Зафиксировать модель, ядро/ABI, носитель, текущие пакеты, WAN/LAN и путь управления.
3. Только после этого выбирать совместимый комплект AWG + tools + LuCI и переходить к установке.

Первую рабочую коробку и MikroTik не менять. Конфиги с ключами, необезличенные отчёты, пароли, Telegram-secret и образы владельцев в репозиторий не загружать. В репозитории должны оставаться воспроизводимые рецепты, шаблоны без секретов и проверенные результаты.

## Как поддерживать документацию

При новом решении сначала актуализировать соответствующую спецификацию, затем добавить запись в журнал решений. Не создавать несколько конкурирующих файлов «финальная версия» и не выдавать проектное решение за работающую функцию. Для результата испытаний указывать версию/commit компонентов и фактически проверенное устройство. Имена будущих пакетов и интерфейсов ниже — предложения, а не уже существующее API.
