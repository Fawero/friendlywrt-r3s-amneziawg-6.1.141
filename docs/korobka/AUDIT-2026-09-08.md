Источник: `scripts/korobka-audit-readonly.sh`, запущенный на новом NanoPi R3S LTS до установки AmneziaWG/Podkop/MTG.

- Firmware: FriendlyWrt / OpenWrt 25.12.2, revision `r32802-f505120278`.
- Target: `rockchip/armv8`, architecture `aarch64`.

- LuCI/uhttpd/rpcd присутствуют.

## APK feeds и фактическое ядро

Подтверждено существенное расхождение между runtime-ядром FriendlyWrt и пакетной базой OpenWrt.

### Runtime

```text
uname -r = 6.1.141
```

Реальный модуль WireGuard расположен здесь:

```text
/lib/modules/6.1.141/wireguard.ko
```

`modinfo wireguard`:

```text
version: 1.0.0
vermagic: 6.1.141 SMP mod_unload modversions aarch64
```

`modules.dep` также находится в `/lib/modules/6.1.141` и соответствует этому модулю.

### APK

При этом APK-база считает установленными:

```text
kernel-6.12.74~4e4117109c72fb4bff0e116d4c7a18f6-r1
kmod-wireguard-6.12.74-r1
```

и описывает пакетный WireGuard как:

```text
/lib/modules/6.12.74/wireguard.ko
```

Однако каталога `/lib/modules/6.12.74` на работающей системе нет. Фактически существует только:

```text
/lib/modules/6.1.141
```

### Репозитории APK

FriendlyWrt настроен на официальные feeds OpenWrt 25.12.2:

```text
https://downloads.openwrt.org/releases/25.12.2/targets/rockchip/armv8/packages/packages.adb
https://downloads.openwrt.org/releases/25.12.2/packages/aarch64_generic/base/packages.adb
https://downloads.openwrt.org/releases/25.12.2/packages/aarch64_generic/luci/packages.adb
https://downloads.openwrt.org/releases/25.12.2/packages/aarch64_generic/packages/packages.adb
https://downloads.openwrt.org/releases/25.12.2/packages/aarch64_generic/routing/packages.adb
https://downloads.openwrt.org/releases/25.12.2/packages/aarch64_generic/telephony/packages.adb
https://downloads.openwrt.org/releases/25.12.2/packages/aarch64_generic/video/packages.adb
```

Также есть локальный feed:

```text
file://usr/local/packages/packages.adb
```

### Вывод

Это гибридная FriendlyWrt-сборка: фактически работающие kernel/modules относятся к FriendlyWrt kernel `6.1.141`, а APK metadata и официальные OpenWrt feeds — к OpenWrt kernel `6.12.74`.

Следствие: нельзя устанавливать готовые `kmod-*` из официальных feeds и нельзя делать массовый `apk upgrade`. Пакет может успешно разрешиться в APK, но его kernel module будет собран под другой ABI и не будет соответствовать реально загруженному ядру.

## Совпадение со старой сборкой AmneziaWG

Имеющийся в репозитории `amneziawg.ko` был собран именно для:

- NanoPi R3S / R3S LTS;
- FriendlyWrt 25.12.2;
- `rockchip/armv8`;
- `aarch64`;
- kernel `6.1.141`;
- vermagic `6.1.141 SMP mod_unload modversions aarch64`.

То есть железо и фактическое загруженное ядро новой коробки полностью совпадают с окружением старой сборки.

Старый модуль остаётся эталонной рабочей базой, но не считается целевой реализацией AWG 3.1.

## Целевая стратегия AmneziaWG 3.1

Современный OpenWrt-порт AmneziaWG уже содержит связку AWG 3.1:

- `kmod-amneziawg` 3.1;
- `amneziawg-tools` 3.1;
- `luci-proto-amneziawg` 3.1.x;
- импорт/экспорт конфигураций и поддержку параметров AWG 3.1 в LuCI.

Для нашей коробки нельзя использовать готовый `kmod-amneziawg` от официальной OpenWrt 25.12.2 сборки, потому что он будет связан с kernel `6.12.74`.

Целевой путь:

1. Собрать `amneziawg.ko` / `kmod-amneziawg` AWG 3.1 строго против FriendlyWrt kernel `6.1.141` и его конфигурации.
2. Проверить vermagic и зависимости на чистой коробке до регистрации модуля.
3. Отдельно установить совместимые userspace `amneziawg-tools` 3.1 и `luci-proto-amneziawg` 3.1.x, не заменяя kernel-пакеты из официального feed.
4. Затем проверить создание/импорт интерфейса через LuCI и CLI.
5. Только после стабильного AWG переходить к Podkop, sing-box и MTG.

## Резервная копия перед AWG 3.1

Перед изменениями создан backup в `/opt/korobka-backups/`:

- `clean-before-awg3-20260909-030140.tar.gz`;
- список пакетов;
- `system-board` metadata.

`sysupgrade -k -b` вывел предупреждения о недоступном package cache для официальных feeds, однако архив конфигурации был создан. Перед использованием backup для восстановления его целостность следует проверить через `tar -tzf`.

## Найдено прежнее build environment AWG 2.0

Пользователь сообщил, что ранее уже успешно собирал AmneziaWG 2.0 kernel module под тот же FriendlyWrt kernel `6.1.141` на собственном сервере.

Это предпочтительная база для сборки AWG 3.1. Если на сервере сохранились kernel tree/build directory, `.config`, `Module.symvers`, cross-toolchain и build scripts, их следует переиспользовать вместо восстановления окружения с нуля. Основная задача — зафиксировать старую рабочую цепочку сборки и заменить исходники AmneziaWG на 3.1, сохранив точный kernel ABI `6.1.141`.

## Решения по безопасности установки

1. Не выполнять `apk upgrade`.
2. Не устанавливать kernel-related APK-пакеты из официальных OpenWrt feeds.
3. Не заменять существующие `/lib/modules/6.1.141/*` пакетами для `6.12.74`.
4. Перед установкой AWG 3.1 сделать резервную копию текущего системного overlay и списка пакетов.
5. Новый AWG-модуль сначала проверять через `modinfo`/`insmod` и только после успешной проверки делать постоянным.
6. Старый `amneziawg.ko` использовать как reference/fallback, но не как финальную целевую версию.

## Следующий этап

На сервере найти прежнее build environment AWG 2.0 под `6.1.141`, снять его структуру и metadata, после чего подготовить воспроизводимую сборку AWG 3.1 под то же ядро и протестировать модуль на новой коробке до установки Podkop.
