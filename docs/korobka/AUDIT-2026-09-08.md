# Обследование чистой коробки — 2026-09-08

Источник: `scripts/korobka-audit-readonly.sh`, запущенный на новом NanoPi R3S LTS до установки AmneziaWG/Podkop/MTG.

## Подтверждено

- Устройство: FriendlyElec NanoPi R3S LTS.
- Firmware: FriendlyWrt / OpenWrt 25.12.2, revision `r32802-f505120278`.
- Target: `rockchip/armv8`, architecture `aarch64`.
- Фактически загруженное ядро: `6.1.141`.
- RAM: ~2 GB.
- microSD: ~64 GB (`mmcblk0`), системный overlay ~1.5 GB; большая пользовательская партиция присутствует отдельно.
- WAN: `eth0`, DHCP, во время обследования адрес `192.168.88.15/24`, default gateway `192.168.88.10`.
- LAN: `br-lan`, адрес `192.168.2.1/24`; в момент обследования интерфейс DOWN.
- Docker bridge присутствует (`172.17.0.1/16`) и выключен.
- В ядре уже загружен обычный WireGuard; присутствуют `tun`, `nft_tproxy`, TPROXY-зависимости и `qrencode`.
- AmneziaWG, Podkop, sing-box и MTG на чистом экземпляре не обнаружены.
- LuCI/uhttpd/rpcd присутствуют.

## Критическое наблюдение по пакетам

Несмотря на `uname -r = 6.1.141`, APK-база показывает пакеты:

- `kernel-6.12.74~...`
- `kmod-wireguard-6.12.74-r1`
- `kmod-tun-6.12.74-r1`
- `kmod-nft-tproxy-6.12.74-r1`

Это означает, что до выяснения происхождения package feeds и фактического расположения модулей нельзя вслепую выполнять `apk add` для kernel-related пакетов и нельзя выполнять массовый `apk upgrade`.

Следующий read-only шаг: проверить `/etc/apk/repositories*`, `apk policy/info`, каталоги `/lib/modules`, `modinfo` для WireGuard и фактический vermagic загруженных модулей.

## Совпадение со старой сборкой AmneziaWG

Имеющийся в репозитории `amneziawg.ko` был собран именно для:

- NanoPi R3S / R3S LTS;
- FriendlyWrt 25.12.2;
- `rockchip/armv8`;
- `aarch64`;
- kernel `6.1.141`;
- vermagic `6.1.141 SMP mod_unload modversions aarch64`.

То есть железо и фактическое загруженное ядро новой коробки совпадают с окружением старой сборки. Однако старый модуль не считаем автоматически подходящим для целевой AmneziaWG 3.1: он хранится как предыдущая рабочая база и эталон совместимости ядра.

## Решение

1. Не устанавливать kernel-related APK-пакеты до выяснения несоответствия 6.1.141/6.12.74.
2. Не выполнять `apk upgrade`.
3. Следующим шагом снять дополнительную read-only диагностику package feeds и модулей.
4. После этого выбрать стратегию AmneziaWG 3.1: готовый совместимый пакет либо собственная сборка под точное FriendlyWrt-ядро 6.1.141.
