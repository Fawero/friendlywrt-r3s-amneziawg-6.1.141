# Образ, обследование, этапы и приёмка

Дата: 8 сентября 2026 года. Статус: план реализации.

## 1. Два разных артефакта

**Общий образ для тиражирования** содержит прошивку, совместимые пакеты, панель, шаблоны, пресеты и механизм активации. Он не содержит данных владельцев.

**Персональный бэкап** содержит настройки и секреты одной коробки и предназначен только для восстановления этого владельца. Это не шаблон для остальных.

Не снимать общий образ с уже персонализированной рабочей карты. Удаления файлов перед raw-копированием недостаточно как гарантии удаления секретов из свободных блоков. Эталон собирается из чистого состояния по воспроизводимому рецепту; не копируется с активно изменяющейся файловой системы.

## 2. Общее и персональное

| Общее в образе | Только в конкретной коробке |
|---|---|
| ОС, пакеты, схемы и код панели | Имя, пароль и идентификатор владельца/устройства |
| Шаблоны интерфейсов, политик и firewall | Загруженные владельцем WireGuard/AmneziaWG-профили |
| Проверенный версионированный пресет | Ключи входящего WireGuard и отдельных телефонов |
| Мастер и механизмы миграции | Telegram-secret, SSH host keys и локальный TLS-ключ |
| Рецепт сборки и тесты | Выбранные адреса, порты, назначения и состояние активации |

Программа использует реквизиты загруженного файла. Дополнительный реестр аккаунтов Surfshark, логинов провайдеров или отдельная процедура запоминания ключей не нужны. Не пытаться локально сгенерировать замену конфигурации удалённого сервера.

Секреты нового экземпляра создаются локально после готовности системного генератора случайных чисел. Не выводить ключи из MAC/времени и не клонировать один и тот же seed как основу идентичности. Пароли и ключи не меняются на каждой загрузке или при импорте нового исходящего профиля.

Переход активации должен быть повторяемым: прерывание питания не создаёт заново уже используемые ключи, обычная перезагрузка не считается новой установкой. Общий пароль или универсальный мастер-токен в образ не включать. Защита первичного захвата владения в доверенной LAN требует реализации и испытаний; конкретный механизм ещё не утверждён.

## 3. Воспроизводимость и обслуживание

Предлагаемый манифест релиза: модель/ревизия платы, target/subtarget, хеш базового образа, kernel/ABI, источники и commit сборки, версии tools/LuCI/Podkop/sing-box/MTG, хеши пакетов, версия пресета, версия схемы конфигурации. Выбранные версии фиксировать только после испытаний.

Нужно сохранять рецепт сборки, а не только `.img`. Предпочтителен небольшой базовый образ с проверенным расширением раздела при первом запуске: карты одинаковой номинальной ёмкости могут иметь разное число секторов. Механизм расширения зависит от реальной разметки и не реализуется до обследования.

Обновлять проверенный согласованный комплект. Не предлагать безусловный `apk upgrade` как обслуживание продукта с внешним kernel-модулем. Предусмотреть миграции, резервную копию и возврат к проверенной версии; контрольные суммы, подписи релизов и лицензии компонентов включить в выпуск.

Factory reset, повторная персонализация, восстановление и обновление — разные операции. Сброс требует отдельного подтверждения владельца. Не выводить технически доступное удаление настроек как уже гарантированное безопасное стирание microSD.

## 4. Что есть в репозитории сейчас

На момент фиксации существуют `amneziawg.ko`, `install-amneziawg.sh`, `build-info.txt`, `device-kernel-info.txt`, `kernel-6.1.141-r3s.config` и исторический README. Их наличие не подтверждает ядро нового устройства или поддержку AWG 3.1.

Исторический README упоминает `setup-awg-podkop-boot.sh`, но файла нет в просмотренном дереве main на 08.09.2026. Не выполнять блок его скачивания как рабочую инструкцию и не восстанавливать скрипт по догадкам. Исторический обход гонок не является требованием новой сборки.

Документация и read-only скрипт добавляются отдельно. Изменений прошивки, установщика и модулей эта фиксация не требует.

## 5. Обследование новой коробки

Следующее практическое действие — [скрипт обследования](../../scripts/korobka-audit-readonly.sh), выполняемый в SSH-сессии **нового** NanoPi. Его можно сначала просмотреть, затем выполнить:

```sh
sh ./scripts/korobka-audit-readonly.sh
```

Путь в примере относится к локальной копии репозитория; скрипт можно перенести отдельно и выполнить через `sh`. Не требуется исполняемый бит и не нужен запуск удалённого установщика через pipe в shell.

Скрипт читает систему, модель, разметку, память, адреса, только маршруты по умолчанию, ограниченный список policy rules, выбранные UCI-поля, пакеты, версии, модули и слушающие порты. Не устанавливает пакеты, не выполняет `uci set/commit`, не меняет firewall/маршруты, не загружает модули, не перезапускает сервисы, не делает исходящих сетевых проверок.

Не выводит приватные ключи и полные конфигурации. Однако IP/MAC, имена интерфейсов и сведения о плате являются метаданными: отчёт нужно просмотреть и обезличить перед публичной публикацией. Сырые результаты не коммитить.

Проверен синтаксис POSIX sh локально. На новой коробке скрипт в рамках подготовки документации не запускался, её вывод ещё не получен. Отсутствие утилиты или данных не считать доказательством отсутствия соответствующей функции.

До анализа отчёта запрещены в рамках текущего шага: сброс, перепрошивка, установка, reboot, смена кабельной схемы/адресов, правки первой коробки и MikroTik. На MikroTik работает большая BGP-таблица; полный дамп маршрутов не нужен.

```text
Текущие пакеты AWG / Podkop / MTG: не подтверждены

```

## 7. Приёмочные проверки

| Область | Проверка |
|---|---|
| Импорт | Один файл при активации; последующее добавление 4+; дубликаты; замена/удаление используемого профиля |
| Безопасность импорта | Невалидный конфиг и shell-хуки не исполняются; секреты не появляются в логах; рабочий профиль сохраняется |
| AWG/LuCI | Согласованные версии, реальная передача данных, изменение через LuCI, повторный запуск после reboot |
| Маршруты | Ни один импорт не захватывает main/default; endpoint не маршрутизируется в самого себя; ответы внешним клиентам возвращаются правильно |
| Политики | Совпадение выбранного и фактического egress; отказ защищённого выхода без скрытого direct fallback |
| DNS/IPv6 | Нет обхода политики через DNS/IPv6; bootstrap без циклических зависимостей; ограничения не ломают разрешённый direct |
| MTG | Реальное подключение Telegram через назначенный upstream; отказ SOCKS виден; служебный порт закрыт со всех внешних зон |
| Телефоны | Два peers, повторный QR, независимый отзыв, права на LAN/интернет, отсутствие доступа к панели |
| Белый IP | Прямой WAN, поддерживаемый роутер перед коробкой, запрещённый проброс, неподтверждённая доступность, смена адреса |
| Автоматизация | Нет полей IP/домен/порт; локальная доступность не выдаётся за доказанную внешнюю |
| Гонки | Холодный старт, WAN down/up, смена адреса, Save & Apply, параллельные попытки применения, отказ одного профиля |
| Клонирование | Две карты из одного чистого образа имеют разные локальные идентичности и секреты; владельцы изолированы |
| Секреты | В образе и Git нет профилей владельцев, ключей, QR с секретами, персональных бэкапов |
| Обслуживание | Проверены прерванная активация, миграция, откат обновления, восстановление персонального бэкапа |

Наличие handshake или слушающего порта — промежуточная проверка, не замена end-to-end теста. Входящие WireGuard и Telegram проверяются раздельно из внешней сети.
